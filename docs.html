Hyperdash Data API

The Hyperdash Data API serves live Hyperliquid market and account state from our own nodes, and history from a verified history store. Every endpoint is read-only and returns JSON by default. Every REST response reports its cost in credits.

What you can query

  • Markets. Perp, spot and HIP-3 markets with live mark, oracle and mid prices, funding, open interest, order books (including the order-level L4 book) and candles from 1 second to 1 month.
  • Accounts. Live positions, margin, open orders, balances, fees and sub-accounts for any wallet, plus fill, funding, ledger and trade history, and batch reads across many wallets.
  • Liquidations. Every liquidation event, plus summaries, cascades and maps of liquidation and stop levels.
  • Analytics. Leaderboards, cohort positioning and flows, trader statistics, network revenue and fees, staking, lending, prediction market outcomes and priority fee flow.
  • Streams. WebSocket channels for trades, liquidations, fills, orders, books and more, billed per event you acknowledge.

How it works

  1. Workspaces and projects. Sign in to the console, create a workspace and pick a plan. Keys belong to a project inside the workspace, so usage is attributed to the key, the project and the workspace.
  2. Keys. Every request carries an API key. Keys read production data and are billed in credits.
  3. Credits. Each request costs a whole number of credits based on the work behind it and the rows it returns. Your plan includes a monthly allowance and you can buy more.
  4. Plan limits. Your plan sets history depth, rate limits, batch sizes and stream connections. They are checked before a query runs, and a refused request costs nothing.
This site is a local replica. The domain in these examples is real, but every request from this page is answered by an in-browser implementation of the same contract, with the same validation, limits and headers. Nothing leaves your browser and no key is required.

Authentication

Every request carries an API key in the Authorization header. Keys are created in the console, belong to a project, and are scoped.

Authorization: Bearer hdk_sk_...

Scopes

A key carries scopes. A request that needs a scope the key does not have returns 403 insufficient_scope and costs nothing.

ScopeGrants

Key lifecycle

  • Shown once. The secret is displayed at creation and never again. The console keeps only a prefix and the last four characters.
  • Revocable. A revoked key returns 401 revoked_key immediately, including on open stream connections, which are re-checked every 5 seconds.
  • Expiry. Keys can expire; an expired key returns 401 expired_key.
  • Agent keys. Agent keys and MCP connections default to 5 requests per second with a burst of 10.

Ranges use start_time and end_time. Leave out start_time to get the endpoint’s default window, often the last 24 hours. The default window never reaches past your plan’s history depth.

List endpoints use cursors. Pass limit and follow next_cursor until has_more is false. A cursor is signed, bound to your workspace and the exact query, and valid for 24 hours. An expired or mismatched cursor returns 400 invalid_parameter.

Responses are capped at 2 MiB. A request that would exceed the cap returns 400 range_too_large: lower limit and page through.

Response formats

List endpoints return JSON by default. Send Accept: text/csv for CSV, or Accept: application/x-ndjson for newline-delimited JSON. In CSV and NDJSON, pagination moves to the X-Has-More and X-Next-Cursor headers.

Async jobs

Async jobs run computations that take too long for a normal request and are available on Growth and up. POST a job with an Idempotency-Key, poll GET /v1/jobs/{id}, then read /v1/jobs/{id}/result. The only job kind today is account_fills_summary.

Using the API

Credits

Each successful request costs a whole number of credits. The cost reflects the work behind the query and, on most list endpoints, how many rows it returns.

credits = multiplier × (base + rows × per_row) + node_read_cost × node_reads
TermMeaning
baseFixed cost of the endpoint.
per_rowCharged per row actually returned, not per row you asked for.
multiplierOn endpoints priced by range, a factor that grows with the range you request (for example ×1 to 1d, ×2 to 7d). A range beyond the endpoint’s maximum returns 400 range_too_large.
node_read_costLive endpoints that read our nodes add a cost per node read. A read served from cache costs nothing.

Reservation

Before a query runs, we reserve its maximum cost against your remaining credits and limits. On most endpoints that maximum is priced at the limit you asked for, plus the maximum node reads. When the query finishes, we charge only what it returned and release the rest. If the maximum does not fit, the request is refused with 403 credits_exhausted and costs nothing.

Controlling spend

  • Quote. GET /v1/quote?route=GET /v1/markets/BTC/trades&limit=1000 returns max_credits and price_version. It is free and runs nothing.
  • Per request. Send X-Max-Credits with the most you accept for one request. A larger request is refused with 403 max_credits_exceeded, free.
  • Price lock. Send X-Credit-Price-Version. If the price changed since, the request fails with 409 price_changed instead of running.
  • Per project and per connection. A project can carry a credit budget, and an MCP connection can carry a day or month budget. The tightest limit wins.

What is free

  • Every failed request (any 4xx or 5xx), including throttled requests and timeouts.
  • GET /v1/me and GET /v1/quote.
  • The public catalog and status endpoints: /v1/datasets, /v1/status, /v1/changelog, /openapi.json, /llms.txt.
  • Creating, listing, polling and cancelling async jobs. Reading a job’s result is billed.

Using the API

Plans and limits

Prices, limits and features of each plan. Limits are checked before a query runs. A request outside your plan costs nothing.

Rate limits

Each workspace has a request rate, a burst allowance and a cap on concurrent requests. The rate works as a token bucket: the bucket holds up to the burst size and refills at the request rate. Data responses carry the policy: the burst, then w, the seconds the bucket takes to refill.

ratelimit-policy: 50;w=2

Requests over the limit return 429 rate_limited and cost nothing.

Concurrent requests count by size

A request uses one slot per 1,000 rows its limit allows, rounded up. On bar endpoints with several rows per bar, it is limit times the rows per bar. Requests of up to 1,000 rows, and most endpoints without a limit, use one slot.

Features by plan

Bulk extraction limits

Each plan caps how many new wallets a workspace can look up, how many wallets its list and snapshot results can name over 30 days, and how many trade tape rows it can read over 30 days. Going over returns 429 extraction_limit: detail says when the request fits again.

Billing periods

  • Yearly plans are billed once a year and receive their credits in monthly slices.
  • Plan credits reset each period, and unused plan credits do not roll over. Purchased credits last 12 months.
  • Upgrades add the difference in credits as soon as the upgrade invoice is paid. Downgrades apply from the next period.
  • There is no free plan: every API key needs an active plan.

Streams

One WebSocket connection carries up to 20 subscriptions. Authenticate with your key in the Authorization header of the upgrade request. Streams are billed per event you acknowledge.

Delivery and billing

  • Events arrive in data batches of up to 100. The next batch waits until you acknowledge the previous one.
  • If you do not acknowledge a batch within 10 seconds, the subscription ends with ack_timeout. Resubscribe from your last cursor.
  • Each acknowledged event costs the channel’s price: 1 credit, or 5 on markets. Replays of events you already paid for are free.

Resuming

Keep the cursor from each data message. After a reconnect, subscribe with it to continue after your last acknowledged batch. Events stay available for about 15 minutes, or about 5 minutes on mids and markets. If what you need is older you get a gap message naming the missing range so you can backfill over REST.

Try the protocol. The stream lab opens a simulated connection with the same message sequence, including a deliberate missed acknowledgement so you can see ack_timeout and the resulting credit accounting.

Using the API

Errors

Errors use RFC 9457 problem details (application/problem+json) with a stable code. Branch on code, never on title or detail.

StatusCodeMeaning and fix

Rate limits and retries

Requests over a rate limit return 429 with a Retry-After header in whole seconds, and retry_after_s in the body. Wait for Retry-After, then double the wait on each further 429, adding random jitter, up to 30 seconds.

Using the API

AI agents and MCP

The hosted MCP server exposes one tool per endpoint, plus time_window and give_feedback. Connect with OAuth (Claude, ChatGPT custom connectors) or send an API key as Authorization: Bearer hdk_sk_….

Tools exposed

Every endpoint in the reference becomes a tool named after its resource and action. Results that name accounts carry hyperdash_links mapping an address to https://hyperdash.com/address/<address>.

Budgeting

An MCP connection can carry a credit budget per day or per month, so an agent cannot spend a workspace’s whole allowance. Exhausted budgets return 403 credits_exhausted.
