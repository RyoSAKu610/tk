Get started

Ticksmith data API

A read-only REST API for Hyperliquid. Each request is answered from the official info endpoint (POST https://api.hyperliquid.xyz/info), normalised into stable snake_case JSON with numeric values, and annotated with where and when the data was fetched.

Base URL— — every path starts with /v1
Upstreamhttps://api.hyperliquid.xyz/info
AuthNone. Public, read-only, rate limited per client IP.
CatalogueGET /v1/endpoints — every route, its parameters, the upstream request types it uses, and what is unavailable
HealthGET /v1/status — uncached round trip to Hyperliquid

What you can query

  • Markets. Every perp market on the main dex and on HIP-3 dexs with mark, oracle, mid, 1 h funding, open interest and 24 h volume; spot pairs; mids; L2 order books; the latest trades; OHLCV candles; funding history.
  • Accounts. For any public wallet: margin summary and spot balances, open positions with liquidation price, open and trigger orders, fills, funding payments, ledger events, and account-value / PnL history.
Nothing is simulated. If Hyperliquid can’t be reached, the API returns a 502/503/504 problem response that names the upstream error. Datasets the official API doesn’t expose — exchange-wide liquidations, leaderboards, open-interest history and so on — are listed under Unavailable data rather than approximated.

Using the API

Responses

Successful responses are application/json with two keys: data (an object or array) and meta.

sourceThe upstream URL the data came from.
upstream_typesThe Hyperliquid info request types behind this endpoint.
fetched_atISO time the oldest upstream response used here was received.
cached / age_msWhether every upstream response came from the short-lived cache, and how old the oldest one is.
upstream_msUpstream round-trip time of the slowest request (0 when cached).
countNumber of rows in data.
request_idAlso in the x-request-id header; quote it when reporting a problem.

Conventions

  • Numbers. Prices, sizes and USD values are JSON numbers parsed from Hyperliquid’s decimal strings (IEEE-754 doubles). Funding is the hourly rate as a fraction (0.0000125 = 0.00125 %/h).
  • Times. Unix milliseconds, UTC. Query parameters start_time / end_time use the same unit.
  • Markets. Perps use Hyperliquid names (BTC, kPEPE), HIP-3 perps use dex:NAME (xyz:XYZ100). Spot accepts the pair (HYPE/USDC) or the spot id (@107). Matching is case-insensitive.
  • Headers. x-cache: HIT|MISS, x-upstream-fetched-at, ratelimit-limit, ratelimit-remaining, ratelimit-reset. CORS is open for GET.

Using the API

Errors

Errors are RFC 9457 application/problem+json with a stable code. Upstream failures include upstream_status and the number of attempts made.

StatuscodeMeaning
400invalid_parameterA parameter is missing, malformed or out of range. Not retried.
404not_foundUnknown route, market or dex. Markets are checked against Hyperliquid’s own metadata.
405method_not_allowedOnly GET (and OPTIONS for CORS) is supported.
429rate_limitedClient rate limit exceeded. Wait for retry-after seconds.
502upstream_errorHyperliquid answered with a non-2xx status after retries.
502upstream_unreachableNetwork failure reaching Hyperliquid after retries.
502upstream_invalidHyperliquid returned a body that isn’t JSON.
503upstream_rate_limitedHyperliquid returned 429 after retries.
503upstream_budgetThis server’s own Hyperliquid weight budget is spent; retry-after says when it frees up.
504upstream_timeoutHyperliquid did not answer within the timeout on every attempt.
500config_errorThe deployment has an invalid environment variable; the detail names it.
See a real errorAsk for a market that doesn’t exist.

Using the API

Rate limits and caching

Two limits protect the service: a per-client token bucket, and a weight budget that keeps this server inside Hyperliquid’s documented 1200 weight per minute per IP.

Loading limits…

Upstream weights

Per Hyperliquid’s documentation: l2Book, allMids, clearinghouseState, spotClearinghouseState and exchangeStatus weigh 2; other info requests weigh 20; recentTrades, userFills, fundingHistory, userFunding and similar add 1 per 20 rows returned; candleSnapshot adds 1 per 60 candles.

Cache lifetimes

DataTTL
Mids, order books, trades1 s
Account state, positions, open orders2 s
Perp market contexts, fills3 s
Candles, spot markets5 s
Funding history, user funding, ledger, portfolio30 s
Perp dexs60 s
Market metadata used to validate coin names5 min
/v1/statusnever
Per isolate. On Cloudflare Workers the cache, the client bucket and the weight budget live in each isolate’s memory, so they are approximate across a busy deployment. Add a Cloudflare rate-limiting rule for a hard global limit.

Configuration and deploy

The backend is one Cloudflare Worker (src/worker/index.js) that serves /v1/* and the static site. All settings are environment variables; invalid values make every API call return 500 config_error naming the variable.

VariableDefaultMeaning
HL_INFO_URLhttps://api.hyperliquid.xyz/infoUpstream info endpoint (https only).
HL_TIMEOUT_MS8000Timeout per upstream attempt.
HL_MAX_RETRIES2Retries for network errors, timeouts, 429 and 5xx.
HL_RETRY_BASE_MS250Base for exponential backoff with jitter.
HL_WEIGHT_BUDGET_PER_MIN900Upstream weight budget (Hyperliquid allows 1200/min/IP).
HL_WEIGHT_MAX_WAIT_MS3000How long a request may wait for budget before 503.
CLIENT_RATE_PER_SEC5Token refill rate per client IP.
CLIENT_BURST20Bucket size per client IP.
CACHE_MAX_ENTRIES500LRU size of the response cache (0 disables it).
CORS_ALLOW_ORIGIN*Value of access-control-allow-origin.
LOG_LEVELinfodebug, info, warn or error. Logs are one JSON object per line.

Deploy

npm install
npm test                 # unit tests + build
npx wrangler login       # once, in your browser
npx wrangler deploy      # builds dist/ and uploads the Worker
npm run verify:live -- https://<your-worker>.workers.dev

Run locally

npm run dev              # build + http://127.0.0.1:4173 with the same /v1 backend
