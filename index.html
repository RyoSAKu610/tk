Datasets and delivery

One API for the whole exchange

Fill, position and liquidation history for every wallet. Trades, order books, liquidations, open interest and funding rate streams. Delivered over REST, WebSocket streams and an MCP server for AI agents.

Fills

grouped by trade

Every fill of one wallet across perps, spot and HIP-3, from our fill history.

GET /v1/accounts/{address}/fillsmax 1,000 rows

Orders

per wallet

Open orders with TP/SL triggers, order history and the fills behind each order.

GET /v1/accounts/{address}/open-ordersmax 2,000 rows

Positions

changes and TWAPs

Live positions and margin, position changes, and every running TWAP slice.

GET /v1/accounts/{address}/positionslive

Liquidations

with closed PnL

Every liquidation with wallet, side, price, notional, realized PnL and mark.

GET /v1/liquidationsmax 2,000 rows

Funding

hourly

Realized funding rates per market, plus each wallet’s funding payments.

GET /v1/markets/{coin}/funding-ratesmax 5,000 rows

Market flows

Follow taker flow, liquidation cascades and funding shifts market by market. Each row is precise, from our own nodes.

GET /v1/cohorts/consensus

Agents and backtests

The hosted MCP server gives an AI agent every endpoint as a tool. Bulk history pages cleanly with cursors into a backtest.

claude mcp add --transport http hyperdash https://data.hyperdash.com/mcp

Credits

One unit for every kind of work

Each successful request costs a whole number of credits based on the work behind it and, on most list endpoints, how many rows it returns. Failed requests are free.

credits = multiplier × (base + rows × per_row) + node_read_cost × node_reads
